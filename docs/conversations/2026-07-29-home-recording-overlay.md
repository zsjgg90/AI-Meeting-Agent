# Home Recording Overlay

## 开发目标

将移动端实时录音从独立全屏录音页改为首页内可展开/收起的录音覆盖层，并在收起后显示 BottomNav 上方迷你录音条。

## 背景

此前首页实时录音会创建会议并跳转 `RecordingScreen`。录音对象、计时、暂停状态和 metering 保存在录音页组件内；页面 `minimized` 时不显示 UI，但没有迷你条。结束录音曾走移动端后台上传、转写和分析提示流程。

## 实现方案

在 `App.tsx` 提升录音显示状态为 `hidden`、`expanded`、`collapsed`，由 App 常驻挂载 `RecordingScreen` 作为共享录音会话组件。`RecordingScreen` 内部保留同一套真实 `expo-av` 录音对象和操作函数，expanded 覆盖层与 collapsed 迷你条只切换 UI，不重新创建或释放录音实例。

## 修改内容

- 首页实时录音创建成功后保持在首页并展开录音覆盖层。
- 新增覆盖层顶部拖拽短横线，下拉超过阈值后收起，距离不足回弹。
- 新增 BottomNav 上方迷你录音条，显示声纹、计时、暂停/继续和结束按钮。
- 完整覆盖层和迷你条共享暂停、继续、结束、放弃、计时和 metering 状态。
- 结束录音停止并释放录音后显示强提示，随后回到首页并复用后台上传、转写和 AI 分析链路。
- 无实时 ASR 时只展示“正在录音，结束后将自动生成会议转写和 AI纪要”，不展示示例转写。
- BottomNav 切换录音中会提示继续录制或放弃录音；继续录制会收起录音层并保持录音。
- 增加迷你条可见时的首页列表底部留白，避免遮挡最后会议卡片。
- 扩展本地 `LucideIcon` 支持 `x` 和 `square` 图标。
- 更新录音上传 UI 静态测试断言为覆盖层流程。

## 影响范围

影响移动端 App 路由承载、首页列表底部留白、实时录音 UI 和录音相关静态测试。未改动 API、Worker、数据库、Prompt、RAG、Validator、文件导入、会议详情、知识库或待办业务合同。

## 测试结果

- `npm run typecheck`：通过。
- `npm run test:recording-upload-ui`：通过。
- `.\scripts\test-all.ps1`：通过。

## 已知限制

当前移动端仍未接入真实流式 ASR、WebSocket 或实时说话人分离；录音中不展示实时转写。跨 Tab 持续录音依赖 App 级常驻挂载，应用进程被系统杀死时不提供后台常驻录音保障。

## 后续建议

- 在真机上补充拖拽阈值、Safe Area、Android 返回键和麦克风权限拒绝场景验收。
- 后续如需真实实时转写，应单独设计移动端 PCM 流、WebSocket 和说话人分离合同。
