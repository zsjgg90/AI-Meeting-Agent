# Recording Overlay Direct Finish UI Simplification

## 开发目标

精简首页录音覆盖层界面，并将结束录音改为直接结束、显示强提示后回首页后台处理。

## 背景

首页录音覆盖层已支持展开和收起，但结束录音仍存在二次确认语义，覆盖层顶部和中部保留了语言选择、关闭按钮、麦克风图标、说明文案和上限提示。最新交互要求录音页更轻量，点击结束后立即进入 AI 结构化分析反馈。

## 实现方案

保留 `expo-av` 真实录音对象、暂停/继续、metering、计时和资源释放逻辑，只调整录音覆盖层 UI 和结束回调。结束按钮直接调用 `stopRecording()`，由 App 显示 `已进入AI结构化分析` 500ms，并启动现有移动端后台 `uploadAudio -> processMeeting -> analyzeMeeting` 流程。

## 修改内容

- 移除结束录音二次确认，结束按钮直接停止并释放录音。
- 恢复并复用 App 内后台处理函数，结束后显示 `已进入AI结构化分析` 强提示 500ms 后回首页。
- 保留会议列表 `处理中` 状态左侧 loading icon。
- 移除顶部 `中文` 选择器和右侧关闭按钮。
- 移除中间麦克风 icon、麦克风下方转写/说明文案。
- 移除播放器上方 `单条录音上限 1 小时` 区域。
- 底部播放器只保留 10 条声纹、较小计时器、暂停/继续和结束按钮，并将声纹移动到计时器左侧。
- 更新录音上传 UI 静态测试断言。

## 影响范围

影响移动端 App 录音结束回调、录音覆盖层 UI、录音相关静态测试和项目文档。未改动 API、Worker、数据库、Prompt、RAG、Validator、Schema、文件导入、会议详情、知识库或待办合同。

## 测试结果

- `npm run typecheck`：通过。
- `npm run test:recording-upload-ui`：通过。

## 已知限制

本次未新增真实流式 ASR、WebSocket 或实时说话人分离。后台处理仍运行在移动端前台 JavaScript 中，如果应用进程在上传或排队前被系统终止，可能需要用户稍后通过首页状态和现有重试能力处理。

## 后续建议

- 在真机验证 500ms 强提示、返回首页时机、Android 返回键和录音权限异常路径。
- 如需更强可靠性，应单独设计后端常驻上传/处理队列。
